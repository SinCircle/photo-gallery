# 个人摄影站重构设计

日期：2026-10-05
状态：已确认，待实施

## 一、背景与目标

现有项目是一个 Vite + TypeScript 的个人摄影展示站（手写 DOM、hash 路由），
部署在 GitHub Pages。图片直接提交进仓库，构建时被复制进 `dist/`。
构建产物已达 237MB（图片占 100%，真正的应用代码只有约 104KB），
在骨架/云构建平台上触发了体积上限。

本次改动：

1. **迁出第三方托管**，改为部署到自有的腾讯云 Docker 容器；
2. **补齐缩略图管线**（现有管线实际未生效，画廊首屏加载的是原图）；
3. **新增网页端管理**（上传、删除、改元数据），独立子页面 + 密码；
4. **重构展示端**：视觉重做（深夜黑基调）+ 液态玻璃 + 物理化动效；
5. **清理历史包袱**（死代码、GitHub Pages 相关配置、构建产物不一致）。

### 现状实测数据

| 项 | 数值 |
|---|---|
| 照片数 | 44 张 |

## 二、已确认的决策

| 决策点 | 结论 |
|---|---|
| 部署方式 | 腾讯云 Docker 容器，**宿主机目录挂载**图片，不重建镜像 |
| 服务端组成 | **Nginx 发静态/图片 + Node 只做 API**（同容器两进程） |
| 元数据存储 | **单个 JSON 索引文件**（不用数据库） |
| 缩略图生成时机 | **上传时同步生成**（720 + 1920 两档） |
| 上传实现 | **直接 POST**（不做分块） |
| 内容组织 | **单池平铺**；不做相册、标签、时间分组、搜索、筛选、地图 |
| 展示体验范围 | 视觉重做 + 单张页交互重做 |
| 前端技术栈 | **Svelte 5** |
| 液态玻璃库 | **naughtyduk/liquidGL**（MIT） |
| 管理端形态 | **独立子页面 + 密码**，路径用默认 `/admin`；画廊页无任何管理入口 |
| 原图可见性 | **完全公开**（任何人可访问原图） |
| 分期顺序 | 后端地基 → 管理端 → 展示端重构 |

### 明确排除（YAGNI）

- 相册 / 标签 / 分类
- 时间分组 / 搜索 / 筛选
- 地图视图（实测仅 25% 照片带 GPS）
- 访问控制（画廊与图片均公开）
- 分块上传、后台上传队列
- AVIF 输出
- 多用户 / 权限体系

## 三、运行时架构

一个 Docker 容器，两个进程：

| 进程 | 职责 |
|---|---|
| **Nginx** | 发送前端静态资源；直接读宿主机目录发送原图与衍生图；将 `/api/` 反向代理到 Node |
| **Node** | 仅处理 `/api/`：登录、上传、删除、修改元数据、读取索引 |

图片请求完全不经过 Node。

### 宿主机目录结构

```
photos/                  ← 宿主机目录，挂载进容器
  originals/             ← 原图（公开可访问）
  thumbs/                ← 720px 衍生图
  web/                   ← 1920px 衍生图
  index.json             ← 唯一索引文件
```

### 请求路由

| 路径 | 处理者 | 说明 |
|---|---|---|
| `/`、`/assets/*` | Nginx | 前端应用外壳 |
| `/media/originals/*` | Nginx | 原图，公开 |
| `/media/thumbs/*`、`/media/web/*` | Nginx | 衍生图，公开，可强缓存 |
| `/api/photos` | Node | 返回索引中的照片列表 |
| `/api/login` | Node | 密码换取会话 |
| `/api/upload`、`/api/delete`、`/api/photo/:id` | Node | 写操作，需会话 |

## 四、数据模型

`index.json` 结构：

```json
{
  "version": 1,
  "updatedAt": "2026-10-05T12:00:00.000Z",
  "photos": [
    {
      "id": "IMG_20260103_160706.jpg",
      "width": 4080,
      "height": 3056,
      "takenAt": "2026-01-03T08:07:06.000Z",
      "title": "",
      "description": "",
      "exif": [
        { "label": "相机", "value": "HUAWEI Pura 70 Ultra" },
        { "label": "光圈", "value": "f/2.1" },
        { "label": "快门", "value": "1/4600s" },
        { "label": "焦距", "value": "15mm" },
        { "label": "ISO", "value": "50" }
      ],
      "derived": { "thumb": true, "web": true }
    }
  ]
}
```

字段说明：

| 字段 | 用途 |
|---|---|
| `id` | 同时是原图文件名，也是 URL 中的标识 |
| `width` / `height` | 前端在图片加载前就能确定宽高比，避免瀑布流跳动 |
| `takenAt` | 拍摄时间；缺失时为 `null`，排序时回退到文件名 |
| `title` / `description` | 管理端可编辑，初始为空 |
| `exif` | 构建期一次性提取，前端不再解析 EXIF |
| `derived` | 衍生图是否就绪；用于标记生成失败的条目 |

排序：按 `takenAt` 倒序，缺失时间的条目按文件名倒序排在后面。

`index.json` 是唯一真相来源。它由 Node 在写操作时更新，不会被运行时请求修改。

## 五、上传流程

```
浏览器选中文件
  → POST /api/upload（multipart，单文件）
  → Node 校验会话
  → 校验扩展名与 MIME
  → 以「时间戳_原名」写入 photos/originals/
  → sharp 同步生成 photos/thumbs/<id>.jpg（720px，inside）
  → sharp 同步生成 photos/web/<id>.jpg（1920px，inside）
  → exifr 提取拍摄时间与 EXIF 字段
  → 追加记录到 index.json，原子写（临时文件 + rename）
  → 返回新记录
```

失败处理：任一衍生步骤失败，记录仍写入索引，但 `derived` 对应字段为 `false`，
前端对该条目回退使用原图，并在响应中标注警告。原图已落盘即视为上传成功，
不因衍生失败而回滚——避免用户重复上传。

## 六、前端

### 技术栈

Svelte 5（编译期响应式，运行时约 2KB）。构建产物是静态文件，由 Nginx 发送。

### 页面

| 路由 | 内容 |
|---|---|
| `#/` | 画廊：深夜黑基调、平铺瀑布流、液态玻璃悬浮 dock |
| `#/photo/:id` | 单张：视觉与交互重做 |
| `#/admin` | 管理：密码登录后上传 / 删除 / 编辑标题描述 |

画廊页面上不出现任何指向 `/admin` 的链接或按钮。

### 视觉方向

基调「深夜黑」：背景压深，让照片成为画面中唯一的亮部。
液态玻璃用在悬浮 dock 上——高对比背景下折射才明显（这也是现有浅色背景
下玻璃质感看不出来的原因）。具体排版、字号、玻璃参数在实施阶段确定，
本文档的设计稿仅为方向示意，不作最终视觉规范。

### 液态玻璃

使用 **liquidGL**（MIT，350KB 解包，无运行时依赖）：

- 渲染链路 WebGPU → WebGL2 → WebGL1 → CSS `backdrop-filter` 自动降级，
  保证低端设备仍有可用的视觉效果，不会白屏；
- `interaction: "fluid"` 提供带粘度的表面位移，是 Apple 液态玻璃手感的核心；
- 内置滚动同步，适配"玻璃 dock 浮在滚动照片墙上"这一主要形态；
- 已知限制：无法折射 CSS 动画（本场景玻璃背后是照片位图，不受影响）。

### 动效（三层）

| 层 | 覆盖对象 | 实现 | 成本 |
|---|---|---|---|
| 一 | 玻璃表面 | liquidGL `interaction: "fluid"` | GPU |
| 二 | 主要控件（dock 按钮、返回、上传、提交） | Svelte 内置 `Spring` | 每控件少量状态 |
| 三 | 海量元素（照片 tile、列表项） | 纯 CSS transform（`transition` + `:active`） | 近乎为零 |

第三层必须用 CSS：照片可达数百张，逐 tile 挂 JS 弹簧会在滚动时压垮主线程。

控件行为规格（第二层）：

| 状态 | 效果 |
|---|---|
| 按下 | 沿压力方向压缩至约 0.96 |
| 拖动 | 非等比缩放：沿拖动轴拉伸、垂直方向收窄（由拖动向量计算 `scale(sx, sy)`） |
| 松手 | 弹簧回弹，带轻微过冲 |
| 点击确认 | 一次短促脉冲 |
| 悬停（桌面） | 轻微上浮 + 倾斜 |

弹簧参数（stiffness / damping）集中为全局常量，一处修改全站生效。

约束：

- **必须尊重 `prefers-reduced-motion`** —— 系统开启"减弱动态效果"时降级为瞬时切换。
- **静止时零开销** —— 仅在交互中与回弹期间运行，停止后完全静止。
